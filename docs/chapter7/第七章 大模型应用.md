# Large model application

## 7.1 LLM review

In recent years, with the rapid development of the field of artificial intelligence, large-scale pre-trained language models (referred to as large models) have become the core force in promoting technological progress. These big models show amazing capabilities in tasks such as natural language processing. However, to accurately measure the performance of a large model, scientific and reasonable evaluation must be relied on.

What is a big model review? Large-model evaluation is to quantify and compare the performance of large-models on different tasks through various standardized methods and data sets. These evaluations not only include the accuracy of the model on a specific task, but also involve multiple aspects such as the generalization ability, inference speed, resource consumption, etc. Through evaluation, we can have a more comprehensive understanding of the actual performance of large models and their potential for application in the real world.

Large models are expensive to develop and involve a large amount of computing resources and data, so evaluation is crucial to ensuring the actual value of the model. First, evaluation can reveal the performance of the model in various tasks, helping researchers and companies to judge the applicability and reliability of the model. Secondly, evaluation can expose potential weaknesses of the model, such as bias, robustness problems, etc., thereby providing a basis for further optimization and improvement. In addition, fair and open evaluations also provide a common standard for the academic and industrial circles, promoting the exchange and progress of technology.

### 7.1.1 LLM's evaluation dataset

In the process of large-scale model evaluation, it is crucial to use standardized evaluation sets. At present, mainstream big model evaluation sets are mainly evaluated from the following aspects. Each evaluation set has its own unique uses and typical application scenarios:

1. **General review set**:
   - **MMLU (Massive Multitask Language Understanding)**: The MMLU evaluation model's understanding ability in a variety of tasks, including various disciplines and knowledge areas. It specifically includes tasks such as history, mathematics, physics, biology, and law, and comprehensively examines the model's knowledge reserves and language understanding abilities in different disciplines.

2. **Tool usage review set**:
   - **BFCL V2**: Used to evaluate the performance of the model in complex tool usage tasks, especially when performing multi-step operations. These tasks usually involve interacting with a database or executing specific instructions to simulate actual tool usage scenarios.

3. **Mathematical Evaluation Set**:
   - **GSM8K**: GSM8K is a data set containing primary school mathematical problems used to test the mathematical reasoning and logical analysis capabilities of models. Specific tasks include arithmetic operations, simple equation solving, numerical reasoning, etc. Although the problems in GSM8K seem simple, the model needs to understand the semantics of the problem and perform correct mathematical operations, reflecting the dual challenges of logical reasoning and language understanding.
   - **MATH**: The MATH dataset is used to test the performance of models on more complex mathematical problems, including algebra and geometry.

4. **Inference Evaluation Set**:
   - **ARC Challenge**: The performance of the ARC Challenge evaluation model in scientific reasoning tasks, especially the answers to common sense and scientific questions. Typical application scenarios include the development of scientific examination questions and the development of encyclopedia question and answer systems.
   - **GPQA**: It is used to evaluate the model's ability to answer open questions under zero sample conditions. It is usually used in customer service chatbots and knowledge question-and-answer systems to help the model give reasonable answers in the absence of specific domain data.
   - **HellaSwag**: The ability of the evaluation model to select the most logical answers in complex contexts, suitable for scenarios such as story sequels and dialogue generation that require high-level understanding and reasoning.

5. **Long text understanding review set**:
   - **InfiniteBench/En.MC**: Evaluate the model's ability to process long text reading comprehension, especially the understanding of scientific literature, and is suitable for application scenarios such as automatic abstracts of academic literature and long report analysis.
   - **NIH/Multi-needle**: used to test the model's understanding and summary ability in a multi-sample long document environment, and is used in scenarios where massive information is required, such as government report interpretation, enterprise internal long document analysis, etc.

6. **Multi-language review set**:
   - **MGSM**: It is used to evaluate the mathematical problem-solving ability of the model in different languages and examine the multilingual adaptability of the model. It is especially suitable for mathematics education and cross-language technical support scenarios in international environments.

The diversity of these evaluation sets helps us comprehensively evaluate the performance of large models in different tasks and application scenarios, ensuring that the models can maintain efficient and accurate performance when dealing with diverse tasks. For example, in the MMLU evaluation, some large models performed well in disciplines such as history and physics, showing a deep understanding of multi-field knowledge; in the GSM8K mathematical evaluation, the latest large models performed close to or even surpassed some human benchmarks in arithmetic and equation solving, showing their potential in complex mathematical inference tasks. These practical evaluation results demonstrate the progress and application potential of the model in various complex tasks.

## 7.2 RAG 

### 7.2.1 Basic principles of RAG

Although the Big Language Model (LLM) has strong language understanding and generation capabilities when generating content, it also faces some challenges. For example, LLMs sometimes generate inaccurate or misleading content, which is called a big model "illusion". In addition, the training data on which the model depends may be outdated, especially when facing the latest information, the accuracy and timeliness of the generated results are difficult to guarantee. For field-specific expertise, LLM is also less efficient in processing and cannot have a deep understanding of complex field knowledge. Therefore, how to improve the generation quality and efficiency of large models has become an important direction of current research.

Against this background, Retrieval-Augmented Generation (RAG) technology emerged and became a major innovation trend in the field of AI. Before generating the answer, RAG first retrieves relevant information from an external large-scale document database and incorporates this information into the generation process to guide and optimize the output of the language model. This process not only greatly improves the accuracy and relevance of content generation, but also makes the generated content more in line with real-time requirements.

The core principle of RAG is to combine "retrieval" with "generating": when a user proposes a query, the system first finds text fragments related to the question through the search module, and then passes these fragments to the language model as additional information, and the model generates more accurate and reliable answers based on this. In this way, RAG effectively alleviates the "illusion" problem of large language models, because the generated content is based on real documents, making the answer more traceable and credible. At the same time, RAG technology has greatly accelerated the update speed of knowledge, allowing the system to absorb and reflect the latest field dynamics in a timely manner.

The document needs to be segmented after reading. We can set a maximum token length and then segment the document according to this maximum length. When dividing documents, it is best to use sentences as units (coarsely divided by `\n`) and ensure that there is some overlap between the fragments to improve the accuracy of the search.

```python
def get_chunk(cls, text: str, max_token_len: int = 600, cover_content: int = 150):
    chunk_text = []

    curr_len = 0
    curr_chunk = ''

    token_len = max_token_len - cover_content
    lines = text.splitlines()  # 假设以换行符分割文本为行

    for line in lines:
        # 保留空格，只移除行首行尾空格
        line = line.strip()
        line_len = len(enc.encode(line))
        
        if line_len > max_token_len:
            # 如果单行长度就超过限制，则将其分割成多个块
            # 先保存当前块（如果有内容）
            if curr_chunk:
                chunk_text.append(curr_chunk)
                curr_chunk = ''
                curr_len = 0
            
            # 将长行按token长度分割
            line_tokens = enc.encode(line)
            num_chunks = (len(line_tokens) + token_len - 1) // token_len
            
            for i in range(num_chunks):
                start_token = i * token_len
                end_token = min(start_token + token_len, len(line_tokens))
                
                # 解码token片段回文本
                chunk_tokens = line_tokens[start_token:end_token]
                chunk_part = enc.decode(chunk_tokens)
                
                # 添加覆盖内容（除了第一个块）
                if i > 0 and chunk_text:
                    prev_chunk = chunk_text[-1]
                    cover_part = prev_chunk[-cover_content:] if len(prev_chunk) > cover_content else prev_chunk
                    chunk_part = cover_part + chunk_part
                
                chunk_text.append(chunk_part)
            
            # 重置当前块状态
            curr_chunk = ''
            curr_len = 0
            
        elif curr_len + line_len + 1 <= token_len:  # +1 for newline
            # 当前行可以加入当前块
            if curr_chunk:
                curr_chunk += '\n'
                curr_len += 1
            curr_chunk += line
            curr_len += line_len
        else:
            # 当前行无法加入当前块，开始新块
            if curr_chunk:
                chunk_text.append(curr_chunk)
            
            # 开始新块，添加覆盖内容
            if chunk_text:
                prev_chunk = chunk_text[-1]
                cover_part = prev_chunk[-cover_content:] if len(prev_chunk) > cover_content else prev_chunk
                curr_chunk = cover_part + '\n' + line
                curr_len = len(enc.encode(cover_part)) + 1 + line_len
            else:
                curr_chunk = line
                curr_len = line_len

    # 添加最后一个块（如果有内容）
    if curr_chunk:
        chunk_text.append(curr_chunk)

    return chunk_text

```

#### Step 3: Vectorization

First, let’s start to implement a vectorized class, which is the basis of the RAG architecture. The vectorization class is mainly used to vectorize document fragments and map a piece of text into a vector.

First, we need to set up a `BaseEmbeddings` base class, so when we use other models, we only need to inherit this base class and then modify it on this basis to facilitate code expansion.

```python
class BaseEmbeddings:
    """
    Base class for embeddings
    """
    def __init__(self, path: str, is_api: bool) -> None:
        """
        初始化嵌入基类
        Args:
            path (str): 模型或数据的路径
            is_api (bool): 是否使用API方式。True表示使用在线API服务，False表示使用本地模型
        """
        self.path = path
        self.is_api = is_api
    
    def get_embedding(self, text: str, model: str) -> List[float]:
        """
        获取文本的嵌入向量表示
        Args:
            text (str): 输入文本
            model (str): 使用的模型名称
        Returns:
            List[float]: 文本的嵌入向量
        Raises:
            NotImplementedError: 该方法需要在子类中实现
        """
        raise NotImplementedError
    
    @classmethod
    def cosine_similarity(cls, vector1: List[float], vector2: List[float]) -> float:
        """
        计算两个向量之间的余弦相似度
        Args:
            vector1 (List[float]): 第一个向量
            vector2 (List[float]): 第二个向量
        Returns:
            float: 两个向量的余弦相似度，范围在[-1,1]之间
        """
        # 将输入列表转换为numpy数组，并指定数据类型为float32
        v1 = np.array(vector1, dtype=np.float32)
        v2 = np.array(vector2, dtype=np.float32)

        # 检查向量中是否包含无穷大或NaN值
        if not np.all(np.isfinite(v1)) or not np.all(np.isfinite(v2)):
            return 0.0

        # 计算向量的点积
        dot_product = np.dot(v1, v2)
        # 计算向量的范数（长度）
        norm_v1 = np.linalg.norm(v1)
        norm_v2 = np.linalg.norm(v2)
        
        # 计算分母（两个向量范数的乘积）
        magnitude = norm_v1 * norm_v2
        # 处理分母为0的特殊情况
        if magnitude == 0:
            return 0.0
            
        # 返回余弦相似度
        return dot_product / magnitude
```

The BaseEmbeddings base class has two main methods: get_embedding and cosine_similarity. `get_embedding` is used to get the vector representation of text, and `cosine_similarity` is used to calculate the cosine similarity between two vectors. When initializing the class, the path of the model and whether it is an API model, for example, using the Embedding API of OpenAI requires setting `self.is_api=True`.

Inheriting the `BaseEmbeddings` class only requires implementing the `get_embedding` method, and the `cosine_similarity` method will be inherited. This is the benefit of writing base classes.

```python
class OpenAIEmbedding(BaseEmbeddings):
    """
    class for OpenAI embeddings
    """
    def __init__(self, path: str = '', is_api: bool = True) -> None:
        super().__init__(path, is_api)
        if self.is_api:
            self.client = OpenAI()
            # 从环境变量中获取 硅基流动 密钥
            self.client.api_key = os.getenv("OPENAI_API_KEY")
            # 从环境变量中获取 硅基流动 的基础URL
            self.client.base_url = os.getenv("OPENAI_BASE_URL")
    
    def get_embedding(self, text: str, model: str = "BAAI/bge-m3") -> List[float]:
        """
        此处默认使用轨迹流动的免费嵌入模型 BAAI/bge-m3
        """
        if self.is_api:
            text = text.replace("\n", " ")
            return self.client.embeddings.create(input=[text], model=model).data[0].embedding
        else:
            raise NotImplementedError
```

## 7.3 Agent

### 7.3.1 What is LLM Agent?

Simply put, the big model Agent is a system that takes LLM as the core "brain" and gives it the ability to independently plan, remember and use tools. It is no longer just passively responding to user prompts (Prompts), but can:

1. Goal Understanding: Receive a relatively complex or high-level goal (for example, “Help me plan a weekend trip to Beijing and book a ticket hotel”).
2. Planning: break down large goals into a series of small steps that can be performed (for example, "search for Beijing attractions", "query weather", "compare air ticket prices", "find the right hotel", "call booking API", etc.).
3. Memory: Have short-term memory (remember the context of the current task) and long-term memory (learning and retrieving information from past interactions or external knowledge bases).
4. Tool Use: Call external API, plug-in or code execution environment to obtain information (such as search engines, databases), perform operations (such as sending emails, booking services), or perform calculations.
5. Reflection & Iteration: (in more advanced Agents) Be able to evaluate your behavior and results, learn from it and adjust follow-up plans.

Traditional LLM is like a knowledgeable librarian who can only talk about it on paper, while LLM Agent is more like an all-round personal assistant. Not only do he know a lot, he can also do his job and even take the initiative to think about the best solutions.

### 7.3.2 Types of LLM Agent

Although the concept of LLM Agent is still developing rapidly, we can roughly divide it into several categories based on its design philosophy and capabilities:

Task-Oriented Agents:
- Features: Focus on completing well-defined tasks in specific areas, such as customer service, code generation, data analysis, etc.
- How to work: There are usually preset processes and specific tool sets that can be called. LLM is mainly responsible for understanding user intent, filling task slots, generating responses or calling appropriate tools.
- Example: A chatbot specifically used for restaurant booking, a code assistant for assisting programming (such as GitHub Copilot reflects the Agent feature in some advanced features).

Planning & Reasoning Agents:
- Features: Emphasize the ability to independently decompose complex tasks, formulate multi-step plans, and adjust according to environmental feedback. They usually require stronger reasoning skills.
- Working method: A specific thinking framework is often adopted, such as ReAct (Reason+Act), allowing the model to first "reasoning" to analyze the current situation and required actions, then execute the "action" to call the tool, and then conduct the next round of thinking based on the results returned by the tool. Chain-of-Thought (CoT) and other prompt engineering techniques are also the basis of their reasoning.
- Example: Research Agents that need to integrate multiple tools such as web search, calculator, database query, etc. to answer complex questions, or agents that can independently complete tasks such as "writing a report on the XX topic and matching relevant data charts".

Multi-Agent Systems:
- Features: Multiple Agents with different roles or abilities work together to achieve a larger goal.
- How to work: Agents can communicate, collaborate, debate and even compete. For example, an Agent is responsible for planning, one is responsible for execution, and one is responsible for review.
- Example: Simulate the software development team (product manager Agent, programmer Agent, tester Agent) to automatically generate and test code; simulate a company organizational structure to complete business planning. Frameworks such as AutoGen, ChatDev support the construction of such systems.

Exploration & Learning Agents:
- Features: This type of agent not only performs tasks, but also actively learns new knowledge, new skills or optimizes its own strategies through interaction with the environment, similar to the concept of Agent in reinforcement learning.
- How to work: May contain more complex memory and reflection mechanisms that enable future planning and actions to be adjusted based on success or failure experience.
- Example: Agents that can independently explore and learn how to operate in an unknown software environment, or continuously improve their strategies while playing games.

#### Step 2: Define tool functions

We define the tool functions that Agent can use in the `src/tools.py` file. Each function needs to have a clear docstring that describes its functions and parameters, as this will be used to automatically generate the tool's JSON Schema.

```python
# src/tools.py
from datetime import datetime

# 获取当前日期和时间
def get_current_datetime() -> str:
    """
    获取当前日期和时间。
    :return: 当前日期和时间的字符串表示。
    """
    current_datetime = datetime.now()
    formatted_datetime = current_datetime.strftime("%Y-%m-%d %H:%M:%S")
    return formatted_datetime

def count_letter_in_string(a: str, b: str):
    """
    统计字符串中某个字母的出现次数。
    :param a: 要搜索的字符串。
    :param b: 要统计的字母。
    :return: 字母在字符串中出现的次数。
    """
    return str(a.count(b))

def search_wikipedia(query: str) -> str:
    """
    在维基百科中搜索指定查询的前三个页面摘要。
    :param query: 要搜索的查询字符串。
    :return: 包含前三个页面摘要的字符串。
    """
    page_titles = wikipedia.search(query)
    summaries = []
    for page_title in page_titles[: 3]:  # 取前三个页面标题
        try:
            # 使用 wikipedia 模块的 page 函数，获取指定标题的维基百科页面对象。
            wiki_page = wikipedia.page(title=page_title, auto_suggest=False)
            # 获取页面摘要
            summaries.append(f"页面: {page_title}\n摘要: {wiki_page.summary}")
        except (
                wikipedia.exceptions.PageError,
                wikipedia.exceptions.DisambiguationError,
        ):
            pass
    if not summaries:
        return "维基百科没有搜索到合适的结果"
    return "\n\n".join(summaries)
# ... (可能还有其他工具函数)
```

In order for the OpenAI API to understand these tools, we need to convert them to a specific JSON Schema format. This can be done with the `function_to_json` helper function in `src/utils.py`.

```python
# src/utils.py (部分)
import inspect

def function_to_json(func) -> dict:
    # ... (函数实现细节)
    # 返回符合 OpenAI tool schema 的字典
    return {
        "type": "function",
        "function": {
            "name": func.__name__,
            "description": inspect.getdoc(func),
            "parameters": {
                "type": "object",
                "properties": parameters,
                "required": required,
            },
        },
    }
```

#### Step 3: Construct the Agent class

We define the `Agent` class in the `src/core.py` file. This class is responsible for managing conversation history, calling OpenAI API, handling tool call requests, and executing tool functions.

```python
# src/core.py (部分)
from openai import OpenAI
import json
from typing import List, Dict, Any
from utils import function_to_json
# 导入定义好的工具函数
from tools import get_current_datetime, add, compare, count_letter_in_string

SYSTEM_PROMPT = """
你是一个叫不要葱姜蒜的人工智能助手。你的输出应该与用户的语言保持一致。
当用户的问题需要调用工具时，你可以从提供的工具列表中调用适当的工具函数。
"""

class Agent:
    def __init__(self, client: OpenAI, model: str = "Qwen/Qwen2.5-32B-Instruct", tools: List=[], verbose : bool = True):
        self.client = client
        self.tools = tools
        self.model = model
        self.messages = [
            {"role": "system", "content": SYSREM_PROMPT},
        ]
        self.verbose = verbose

    def get_tool_schema(self) -> List[Dict[str, Any]]:
        # 获取所有工具的 JSON 模式
        return [function_to_json(tool) for tool in self.tools]

    def handle_tool_call(self, tool_call):
        # 处理工具调用
        function_name = tool_call.function.name
        function_args = tool_call.function.arguments
        function_id = tool_call.id

        function_call_content = eval(f"{function_name}(**{function_args})")

        return {
            "role": "tool",
            "content": function_call_content,
            "tool_call_id": function_id,
        }

    def get_completion(self, prompt) -> str:

        self.messages.append({"role": "user", "content": prompt})

        # 获取模型的完成响应
        response = self.client.chat.completions.create(
            model=self.model,
            messages=self.messages,
            tools=self.get_tool_schema(),
            stream=False,
        )
        
        # 检查模型是否调用了工具        
        if response.choices[0].message.tool_calls:
            self.messages.append({"role": "assistant", "content": response.choices[0].message.content})
            # 处理工具调用
            tool_list = []
            for tool_call in response.choices[0].message.tool_calls:
                # 处理工具调用并将结果添加到消息列表中
                self.messages.append(self.handle_tool_call(tool_call))
                tool_list.append([tool_call.function.name, tool_call.function.arguments])
            if self.verbose:
                print("调用工具：", response.choices[0].message.content, tool_list)
            # 再次获取模型的完成响应，这次包含工具调用的结果
            response = self.client.chat.completions.create(
                model=self.model,
                messages=self.messages,
                tools=self.get_tool_schema(),
                stream=False,
            )

        # 将模型的完成响应添加到消息列表中
        self.messages.append({"role": "assistant", "content": response.choices[0].message.content})
        return response.choices[0].message.content
```

The Agent's workflow is as follows:

1. Receive user input.
2. Call the big model (such as Qwen) and inform it of the tools available and its schema.
3. If the model decides to call the tool, the Agent will parse the request and execute the corresponding Python function.
4. Agent returns the execution results of the tool to the model.
5. The model generates a final reply based on the tool results.
6. Agent returns the final reply to the user.

#### Step 4: Run Agent

Now we can instantiate and run Agent. A simple command-line interaction example is provided in the `if __name__ == "__main__":` section of `demo.py`.

```python
# demo.py (部分)
if __name__ == "__main__":
    client = OpenAI(
        api_key="YOUR_API_KEY", # 替换为你的 API Key
        base_url="https://api.siliconflow.cn/v1",
    )

    # 创建 Agent 实例，传入 client、模型名称和工具函数列表
    agent = Agent(
        client=client,
        model="Qwen/Qwen2.5-32B-Instruct",
        tools=[get_current_datetime, add, compare, count_letter_in_string],
        verbose=True # 设置为 True 可以看到工具调用信息
    )

    # 开始交互式对话循环
    while True:
        # 使用彩色输出区分用户输入和AI回答
        prompt = input("\033[94mUser: \033[0m")  # 蓝色显示用户输入提示
        if prompt.lower() == "exit":
            break
        response = agent.get_completion(prompt)
        print("\033[92mAssistant: \033[0m", response)  # 绿色显示AI助手回答
```
