## 📖 Why is there an Extra Chapter?

&emsp;&emsp;Based on the Happy-LLM main tutorial, we found that there are many excellent learners and practitioners in the community who have accumulated valuable experience, unique insights and practical skills in learning and using large language models. Although these contents do not belong to the core knowledge system of the main tutorial, they are of great value for in-depth understanding and application of large language models.

**Purpose of the establishment of Extra Chapter: **

- 🌟 **Gathering wisdom**: Collect excellent study notes, practical experience and technical blogs from community members
- 🔄 **Continuous update**: Maintain the timeliness of content and keep up with the rapid development of the field of large language models
- 🤝 **Promote communication**: Provide a platform for sharing and communication for community members
- 📚 **Supplement and improvement**: It provides useful supplements and extensions to the main tutorial content
- 💡 **Inspiring thinking**: Inspire readers' deep thinking through different perspectives and practical cases

**Extra Chapter contains content types: **

- 📝 **Study Notes**: Deep Learning Experience and Knowledge Summary
- 🛠️ **Practical Cases**: Application Experience in Real Projects
- 🔬 **Technical Exploration**: Research and Experiment of Frontier Technologies
- 💭 **Thinking and Insights**: Unique insights into the development of large language models
- 🎯 **Special research**: In-depth analysis of specific areas or problems

## 📋 PR Contribution Specification

&emsp;&emsp;We warmly welcome community members to contribute high-quality content to Extra Chapter! To ensure the quality of content and the integrity of the project, please follow the following specifications:

### 🗂️ Directory structure specification

The content of each contribution should be organized in the following directory structure:

```
Extra-Chapter/
├── your-topic-name/                    # 你的主题文件夹
│   ├── readme.md                       # 主要内容文件（必需）
│   ├── images/                         # 图片资源文件夹（可选）
│   │   ├── figure1.png
│   │   └── figure2.jpg
│   ├── code/                           # 代码文件夹（可选）
│   │   ├── example.py
│   │   └── requirements.txt
│   ├── data/                           # 数据文件夹（可选）
│   │   └── sample_data.json
│   └── notebook.ipynb                  # Jupyter Notebook（如涉及代码必选）
└── Readme.md                           # 本文件
```

### 📝 File naming specifications

1. **Theme folder naming**:
   - Use lowercase letters and hyphens
   - The name should be concise and clear, and be able to summarize the topic content
   - For example: `why-fine-tune-small-large-language-models`, `rag-optimization-techniques`

2. **Main content files**:
   - Must be named `readme.md`
   - Written in Markdown format

3. **Picture File**:
   - Place it in the `images/` folder
   - Use a descriptive file name
   - Supported formats: `.png`, `.jpg`, `.jpeg`, `.gif`, `.svg`

4. **Code File**:
   - If code is involved, please try to provide Jupyter Notebook files that can be run directly
   - Place it in the `code/` folder
   - Use standard file extensions
   - If you have a dependency, please provide `requirements.txt`
   - If there is a Jupyter Notebook file, please place it in the main folder

### ✍️ Content quality requirements

1. **Originality**:
   - Content must be original or authorized
   - If you quote other people's content, please indicate the source

2. **Technical Accuracy**:
   - Ensure the accuracy of technical content
   - The code example should work properly
   - Provide necessary environmental instructions

3. **Clear structure**:
   - Use clear title hierarchy
   - Use lists, tables and other formats reasonably
   - Use appropriate emphasis on important content

4. **Language Specification**:
   - Use standard Chinese expression
   - Accurate use of technical terms
   - Avoid typos and syntax errors

- New theme folder name
- An overview of contributions
- Detailed description of contributions
- Your Github personal homepage link and your personal introduction
